# Data Acquisition, Preprocessing & Setup Guide

This document outlines the data sources, acquisition pipelines, and preprocessing methodologies used in **HarmonyShield**.

---

## 1. Data Sources

HarmonyShield evaluates detection performance using two complementary sources:

### A. FakeMusicCaps (AI-Generated Class)
- **Source:** Synthetic music benchmark generated using text prompts from the Google MusicCaps dataset.
- **Generators Represented:**
  - `audioldm2` (AudioLDM 2)
  - `stable_audio_open` (Stable Audio Open)
  - `musicldm` (MusicLDM)
  - `mustango` (Mustango)
  - `MusicGen_medium` (Audiocraft / MusicGen Medium)
- **Structure:** 10-second audio clips paired with prompt metadata matching original MusicCaps records.

### B. Google MusicCaps (Human-Composed Class)
- **Source:** Publicly released dataset of 5,521 YouTube music clips with high-quality human expert descriptions and genre/instrument labels.
- **Reference Format:** YouTube Video ID (`ytid`), `start_s`, `end_s`, and textual caption.

---

## 2. Human Audio Acquisition Pipeline

The original MusicCaps dataset distributes YouTube references rather than direct WAV files. To assemble the human reference class:

1. **Clip Sampling:** YouTube video identifiers (`ytid`) are queried for the corresponding time intervals `[start_s, end_s]`.
2. **Audio Download:** Audio streams are extracted using `yt-dlp` at best available audio quality.
3. **Strict Window Trimming:** An `ffmpeg` post-processing stage strictly enforces a **10.000-second** window matching `[start_s, end_s]` to eliminate surrounding keyframe drift.
4. **Standardization:** Audio is normalized, converted to single-channel (mono), and resampled to **16,000 Hz** (or 22,050 Hz depending on pipeline stage).
5. **Auditing & Manifesting:** A resumable JSON manifest records:
   - `ytid`
   - Requested start/end seconds
   - Final actual duration (must equal 10.000 s)
   - Sample rate & channel count
   - Verification status

Manifests are stored in `data/musiccaps_human_pilot/manifest.json`.

---

## 3. Pilot Dataset & Group Isolation

To evaluate generalization while strictly preventing data leakage:

- **100 Human Clips** are matched with **100 AI clips** from each of the 5 generators (totaling 600 clips).
- **Group Isolation by YouTube ID (`ytid`):** Since synthetic clips are generated from MusicCaps prompts corresponding to specific YouTube IDs, any split performed at the clip level would allow the same musical idea/text prompt to appear in both training and test sets.
- **Methodology:** An 80/20 train/test split is strictly enforced at the `ytid` group level using `GroupShuffleSplit`.
- A programmatic leakage audit (`experiments/generator_generalization/LEAKAGE_AUDIT.md`) verifies:
  $$\text{Train } ytid \cap \text{Test } ytid = \emptyset$$

## 4. Pre-Extracted Feature Tables (Zero-Download Reproduction)

To allow complete scientific reproduction without downloading hundreds of megabytes of raw audio files, extracted feature tables are tracked in `data/pilot_dataset/`:

| File | Description | Dimensions |
|---|---|---|
| `dataset.csv` | Full metadata manifest of the 600-clip pilot dataset | 600 rows |
| `features_A.csv` | MFCC features (20 coefficients $\times$ mean/std) | 40 features |
| `features_B.csv` | Spectral features for Pilot 01 (AudioLDM2 vs Human) | 14 features |
| `features_B_all.csv` | Spectral features across all 5 generators | 600 rows $\times$ 14 features |
| `features_C.csv` | MFCC + Spectral features | 54 features |
| `features_D.csv` | MFCC + Spectral + Harmonic features | 80 features |
| `features_E.csv` | Full engineered feature set (Spectral, MFCC, Harmonic, Energy, Temporal) | 85 features |

Researchers can train and evaluate classical models directly on these CSVs using `src/models/trainer.py` or `scripts/train_resnet.py`.

---

## 5. External Black-Box Demonstration Audio

To test real-world out-of-distribution behavior, two external tracks were curated under `data/external_demo/`:
1. **Suno AI Generation:** A full song generated by Suno (an unseen commercial generator not present in FakeMusicCaps).
2. **Human Composition:** An independently produced human music recording (`Hangova`).

Neither track was used for model training, validation, threshold tuning, or model selection.
